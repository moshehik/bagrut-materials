# מראת קטגוריות (category mirror)

## למה
באתר שני עצי קטגוריות עם שמות תיקיות זהים: `torah/5-units/school-based-electives/chalufa-a/...` (שם נמצאים החומרים) ו-`torah/3-units/internal/school-based-electives/chalufa-a/...` (אותה תוכנית; ויחי פרקים מז–נ ווזאת הברכה פרקים לג–לד). מורות שנכנסות דרך עץ 3 היחידות ראו "התיקייה ריקה". במקום להעתיק קבצי Drive/שורות DB, התיקיות הריקות בעץ 3 מציגות בקוד את חומרי התיקייה התואמת בעץ 5. החומרים שומרים על ה-id שלהם, ולכן `/api/download/ID`, תצוגה מקדימה, מכסות ותיקוני קבצים עובדים כרגיל.

## איפה
הכול ב-[src/lib/data.ts](../src/lib/data.ts):

- `CATEGORY_MIRRORS` – טבלת זוגות `[קידומת-משקפת, קידומת-מקור]` של נתיבי slugs (הקידומת כוללת את התיקייה עצמה וכל תתי-התיקיות). כרגע זוג אחד.
- מפת המראה נבנית מכל הקטגוריות (נתיב slugs לכל קטגוריה) ונשמרת בזיכרון 60 שניות לכל instance. תיקייה נכנסת למפה רק אם יש לה מקבילה בנתיב המקור **ואין לה חומרים משלה בכלל** (בכל סטטוס) – העתקים אמיתיים (למשל בבמדבר חלופה ב/ג) והעלאה עתידית לתיקייה משקפת ממשיכים לעבוד כרגיל. כשל בטעינה = בלי מראות (לא מפיל עמוד).
- API: `mirrorSourceId(id)` (המקור, או ה-id עצמו), `expandMirrorIds(ids)` (הרשימה + מקורות), `mirrorRelatedIds(ids)` (דו-כיווני + אבות, לבדיקות כיסוי רכישה), `getMirrorMap()` (למפת id→id בשאילתות SQL).

## איפה הוחל
| מקום | מה |
|---|---|
| `getVisibleMaterials` | עמוד התיקייה (גם למנהלת) מציג את חומרי המקור. עמוד הניהול `/admin/materials` משתמש ב-`getMaterials` ולכן עדיין מציג את התיקייה עצמה (ריקה). |
| `countMaterialsUnder` | ה-SQL כולל גם את חומרי המקור של כל צומת משקף בתת-העץ (כרטיסי תיקיות ומונים). |
| `getFreeCategoryIds` | חומרי המקור נחשבים כחומרי התיקייה המשקפת (תגית "חינם" גם בעץ 3 ובאבות). |
| `isFreeUnit`, `userCanUseUnitForum` | לפי תיקיית המקור. |
| `checkEntitlement` | מזהי השרשרת מורחבים בתיקיות המשקפות ואבותיהן: קובץ מורחב/מנוי שנרכש דרך עץ 3 מכסה את החומר. נוסף `getCategoryChainOnce` (פעם אחת לבקשה). |
| `download-folder/[id]` | "הורדת כל הקבצים"/"שליחה למייל" מתיקייה משקפת. |
| `purchase.ts`, `checkout/page.tsx`, `purchase-helpers.ts`, `nedarim/items.ts` | מחיר וספירת קובץ מורחב כוללים את חומרי המקור; `isLeaf` ותווית ההנחה נקבעים מעץ התיקייה עצמה (לא מהרשימה המורחבת). `itemCoverageFor` בודק "כבר שלך" גם דרך המראה. |
| `purchase-cancel.ts` | זיהוי הורדות מחומרי המקור לצורך ביטול קובץ מורחב. |
| `home-personal.ts` | תיקייה משקפת נחשבת "שיעור" בשיעור הבא בתור. |

לא שונה בכוונה: אינדקס החיפוש (החומרים מופיעים רק תחת עץ 5 – בלי תוצאות כפולות), `download-groups.ts` (הורדות נרשמות לפי `materials.categoryId`, כלומר עץ המקור), פורום היחידה (נפרד לכל תיקייה), `bundlePrice` ידני (נקבע על קטגוריית ה-3 עצמה, לא יורש מהמקור).

## הוספת זוג
שורה אחת ב-`CATEGORY_MIRRORS`, למשל `["torah/3-units/internal/school-based-electives/chalufa-d", "torah/5-units/school-based-electives/chalufa-d"]`. אין צורך במיגרציה. תיקייה ללא מקבילה (למשל haazinu/perek-32 שקיימת רק בעץ 5) פשוט לא נכנסת למפה.

## בדיקה
`NODE_OPTIONS=--use-system-ca npx tsx --conditions=react-server scripts/_verify-category-mirror.mts` (קריאה בלבד מול ה-DB): מדפיס את מפת המראה, ספירות לכל תיקייה משקפת מול המקור, ו-`countMaterialsUnder` להורים.
